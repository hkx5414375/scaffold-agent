# ADR 0002：文件归属与确定性事务

- 状态：已接受
- 日期：2026-08-31

## 背景

不同 AI 编码助手会以不同顺序调用 Engine，也可能在两次生成之间直接修改项目。Engine 必须能区分“能力包生成的文件”和“用户已有或后来手改的文件”，并确保进程中断不会留下半套代码。

## 决策

1. `.scaffold-agent/manifest.json` 是项目内唯一的文件归属真相源，记录 Blueprint 哈希、能力版本锁、文件路径、能力所有者和最近一次应用后的 SHA-256。
2. 未登记在清单中的现有文件一律视为用户文件，生成、升级和缩减都不得覆盖或删除。
3. 已登记文件的实际哈希与清单不一致时，视为用户修改，普通计划停止；丢失的托管文件只能通过 `repair` 动作重建。
4. 所有写入先形成不可变 Plan，并验证创建、修改和删除操作的前置哈希。
5. 新内容先写入项目内临时区，旧内容移动到按 Plan ID 隔离的备份区，再用同文件系统重命名完成替换。
6. 归属清单是事务的最后一个变更；只有代码文件全部成功后才更新清单。
7. 每完成一步都追加新的 Journal 快照。显式回滚先校验应用后哈希；中断恢复根据目标文件、备份和 Journal 恢复到应用前状态。
8. 所有路径使用正斜杠的规范相对路径，并在解析符号链接后再次验证项目根目录边界。

## 结果

- 同一项目状态和同一输入会得到同一个 Plan ID。
- Engine 不会静默接管用户文件，也不会覆盖用户对托管文件的修改。
- 应用、回滚和中断恢复可以在 Windows、Linux、macOS 使用同一套规则。
- 初始版本采用整文件归属和显式扩展点；AST 级合并不属于当前事务层职责。
