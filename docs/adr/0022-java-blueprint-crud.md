# ADR 0022：Java 蓝图 CRUD 与双数据库一致性

- 状态：已接受
- 日期：2026-09-01

## 背景

Java 适配器已经具备身份认证与权限控制，但 AI 若仍需逐项目编写实体、控制器、事务、SQL、迁移和测试，就无法达到脚手架减少重复代码与 Token 消耗的目标。Java 生成结果还必须与 Go 版共用一份蓝图语义，并在 PostgreSQL 和 MySQL 上保持可验证的一致行为。

## 决策

1. `java-service` 升级到 `0.3.0`，并增加独立锁项 `java-crud` `0.1.0`。
2. 首个 Java CRUD 切片接受一个模块和一个实体，支持 `string`、`text`、`bool`、`int64`、`datetime` 字段以及精确的 create/read/update/delete 权限集合。
3. 生成 Spring MVC 控制器、无 HTTP 依赖的应用服务、JDBC 仓储接口与实现、Flyway 迁移、OpenAPI 3.1、服务单元测试和隔离数据库集成测试。
4. 列表接口采用按 `id` 排序的有界游标分页，单页最多 100 条；更新和删除必须携带正整数版本，数据库使用条件写入实现乐观并发控制。
5. `int64` 字段和版本在 HTTP JSON/OpenAPI 中使用十进制字符串，避免不同 AI 客户端或 JavaScript 前端丢失 64 位整数精度。
6. 创建、更新、删除与成功审计记录在同一数据库事务内提交。唯一约束和陈旧版本统一映射为稳定的 HTTP 409，缺失记录映射为 404，输入错误映射为 400。
7. PostgreSQL 使用双引号标识符和 `timestamptz`，MySQL 使用反引号标识符和 `datetime(6)`；数据库差异只存在于生成模板，不进入蓝图。
8. CI 对两个数据库分别生成并执行 Maven `verify`；真实数据库作业还会创建随机 Schema 或数据库，重复运行迁移，执行 CRUD、乐观锁、权限种子和审计验收，然后删除隔离范围。

## 结果

- AI 只需描述业务字段和权限，不再重复编写 Java CRUD 基础设施。
- 生成项目运行时不依赖 Scaffold Agent，仍可由人工或任意 AI 正常扩展。
- Java 已达到后端 CRUD 基线；Vue 管理端和平台能力仍作为后续兼容切片推进。
