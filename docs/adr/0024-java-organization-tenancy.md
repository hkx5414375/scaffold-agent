# ADR 0024：Java 组织租户基础能力

- 状态：已接受
- 日期：2026-09-01

## 背景

Java CRUD 若只依赖全局管理员角色，就无法安全承载多个组织的数据。后续文件、任务、通知、审批等平台能力也必须先有统一的组织身份、成员角色和数据库隔离条件。

## 决策

1. Java 适配器支持 `organization-tenancy` `0.1.0`，与 Go 共用同一蓝图选择和 `X-Organization-ID` 传输约定。
2. 组织创建、创建者管理员成员关系和成功审计在同一事务提交；组织列表只返回当前身份拥有成员关系的组织。
3. 带 `tenantScoped = true` 的权限注解先解析组织成员角色，再检查该角色的权限。缺失成员关系、无权限和未知组织统一返回 403，并记录有界的拒绝审计。
4. 认证 Principal 只在租户授权成功后附加 `organization_id` 和组织内角色，业务服务拒绝没有组织上下文的调用。
5. 所有业务创建、读取、列表、更新和删除 SQL 都携带组织条件；唯一字段改为组织内复合唯一约束，跨组织标识统一表现为不存在。
6. PostgreSQL 与 MySQL 分别生成组织迁移，业务表引用组织外键。隔离集成测试重复执行迁移、创建组织、验证允许与拒绝授权、执行 CRUD 并核对审计。
7. 共享 Vue 管理端发现并保存当前组织，所有业务请求自动发送组织头；锁文件安装、测试、类型检查和生产构建继续作为 CI 门禁。

## 结果

- Java 后续平台能力可以复用统一租户边界，不需要各自实现组织校验。
- Go 与 Java 的基础组织工作流一致；成员管理 `0.2.0` 和生命周期 `0.3.0` 仍需继续移植到 Java。
