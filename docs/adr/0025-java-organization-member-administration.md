# ADR 0025：Java 组织成员管理

- 状态：已接受
- 日期：2026-09-01

## 背景

Java 的 `organization-tenancy` `0.1.0` 已经建立组织范围和数据库隔离，但只有组织创建者能进入组织，仍不足以支持实际团队协作。成员邀请和管理员变更涉及一次性秘密、邮箱身份绑定、并发事务与审计，不能让不同 AI 在业务项目里重复设计。

## 决策

1. Java 适配器支持 `organization-tenancy` `0.2.0`，保留 `0.1.0` 可选，并只新增 `V000060__organization_members.sql`；已经执行的 `V000050__organization_tenancy.sql` 保持字节不变。
2. 管理员可以列出成员、创建邀请、调整角色和移除成员；普通成员只能读取成员列表。HTTP 路径中的组织标识必须与经过 `X-Organization-ID` 授权后的 Principal 一致。
3. 邀请绑定规范化邮箱并在 72 小时后过期。创建响应只返回一次明文接受 Token，数据库只保存 SHA-256 十六进制摘要。
4. 接受邀请必须使用已认证身份的同一邮箱。未知、过期、已接受和邮箱不匹配统一返回 `tenancy.invitation.invalid`，不暴露邀请状态。
5. 创建邀请、接受邀请、角色变更和成员移除都先锁定组织行。管理员降级和移除在同一事务内检查管理员数量，保证并发操作不能删除最后一个管理员。
6. 成功和拒绝的成员变更都在决定结果的同一事务写入审计事件；公开错误使用稳定代码，不返回数据库原因。
7. PostgreSQL 与 MySQL 使用各自的增量迁移和相同服务契约。真实数据库测试并发发起两个管理员降级，必须恰好一个成功、一个得到最后管理员冲突。
8. 共享 Vue/Element Plus 管理端加入成员列表、邀请 Token 一次性展示、角色调整、移除和邀请接受，并继续通过锁定依赖的 Lint、Vitest、类型检查、生产构建和格式门禁。

## 结果

- Java 生成项目具备可直接使用的组织协作入口，AI 不需要重新实现安全敏感的邀请和成员事务。
- 组织所有者、改名、停用和重新启用仍属于 `0.3.0`，下一阶段单独实现，避免改变 `0.2.0` 的成员契约。
