# ADR 0026：Java 组织生命周期与所有权

- 状态：已接受
- 日期：2026-09-01

## 背景

Java 的 `organization-tenancy` `0.2.0` 已支持成员协作，但管理员角色不能表达谁拥有组织，也不能安全地停用租户。直接删除组织会级联删除业务数据，不适合作为通用脚手架的默认能力。

## 决策

1. Java 适配器支持 `organization-tenancy` `0.3.0`，在 `0.2.0` 上只新增 `V000070__organization_lifecycle.sql`，`V000050` 与 `V000060` 保持字节不变。
2. 组织创建者同时成为所有者和管理员。所有权独立于可复用的 `admin`、`user` 角色，并通过 `owner_user_id` 唯一记录。
3. 活跃组织的管理员可以改名。只有当前所有者可以转移所有权、停用和恢复组织；生命周期路由只要求身份认证，由事务仓库核对成员、角色、所有者和状态，因此所有者能恢复已经停用的组织。
4. 所有权只能转给现有成员，事务会把新所有者提升为管理员，原所有者仍保留管理员角色。所有者在转移前不能被降级或移除。
5. 生命周期、角色和成员变更先锁定同一组织行。成功与拒绝审计都在决定结果的同一事务提交，公开错误不泄露其他组织、成员或所有者信息。
6. 停用只写入 `inactive` 状态和停用时间，不删除任何租户数据。组织仍出现在成员列表中，但租户授权查询只接受 `active`，因此业务、成员和其他用户范围操作立即被阻断。
7. OpenAPI 与共享 Vue/Element Plus 管理端加入改名、所有权转移、停用、恢复、非活跃标识和所有者保护。管理端仍执行锁定依赖的 Lint、Vitest、类型检查、生产构建和格式门禁。
8. PostgreSQL 与 MySQL 的真实数据库测试覆盖所有者保护、非所有者拒绝、成员自动提升、停用授权阻断、数据保留和恢复后重新授权。

## 结果

- Java 与 Go 的 `organization-tenancy` `0.1.0`、`0.2.0`、`0.3.0` 契约对齐。
- 永久删除和数据保留期限继续由具体业务项目显式实现，Scaffold Agent 不生成破坏性组织删除接口。
