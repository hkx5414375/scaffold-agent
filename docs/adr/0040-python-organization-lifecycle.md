# ADR 0040: Python 组织生命周期与所有权

- Status: Accepted
- Date: 2026-09-01

## Context

Python `organization-tenancy` `0.2.0` 已能邀请和管理成员，但管理员角色不能表示组织最终归属，也不能安全暂停一个租户。生成级联删除接口会让业务数据难以恢复，而只在 HTTP 层判断所有者又会留下并发绕过空间。

## Decision

1. Python 适配器支持 `organization-tenancy` `0.3.0`，保留 `0.1.0`、`0.2.0` 可选，并只新增 `000070_tenancy_lifecycle`；`000050` 与 `000060` 保持字节不变。
2. 创建者同时成为所有者和管理员。所有权通过组织表的 `owner_user_id` 单独记录，不新增可复用 RBAC 角色。
3. 活跃组织的管理员可以改名。只有当前所有者可以转移所有权、停用和恢复组织；生命周期接口只要求完成身份认证，再由事务仓储核对成员、角色、所有者和状态，因此停用后的所有者仍可恢复组织。
4. 所有权只能转给现有成员，事务会把新所有者提升为管理员，原所有者仍保留管理员。当前所有者在转移前不能被降级或移除。
5. 生命周期、成员角色和移除操作先锁定同一组织行。成功与拒绝审计都在决定结果的同一事务内提交。
6. 停用只写入 `inactive` 与停用时间，不删除组织、成员或业务数据。组织仍出现在成员列表中，但租户授权只接受 `active`。
7. 稳定 OpenAPI 和共用 Vue/Element Plus 管理端加入改名、所有权转移、停用、恢复、非活跃标识和所有者保护。
8. SQLite 实际执行完整 Alembic 迁移图；PostgreSQL 与 MySQL 真库门禁验证所有者权限、成员自动提升、停用阻断、数据保留、恢复和审计。

## Consequences

- Go、Java、Python 的组织生命周期契约对齐，AI 可跨语言使用同一操作顺序和安全假设。
- 停用是可恢复的业务状态，不等于删除，也不会触发级联数据清理。
- 永久删除、法务保留期和匿名化继续由具体业务显式实现，脚手架不猜测这些策略。
