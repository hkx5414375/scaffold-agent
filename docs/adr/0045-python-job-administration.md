# ADR 0045：Python 后台任务管理

- 状态：已接受
- 日期：2026-09-01

## 背景

可靠后台任务需要可观测的运维入口，但任务载荷、作用域键和幂等键可能包含业务或安全敏感信息。让管理员直接操作任务表还会绕过租户隔离、状态约束和审计事务，尤其容易误重试运行中任务。

## 决策

1. Python `job-administration` `0.1.0` 依赖 `background-jobs` `^0.1.0`；单独选择时由能力解析器自动加入并锁定可靠任务能力。
2. `GET /api/v1/jobs` 只返回最多 100 条任务元数据，支持 `queued`、`running`、`succeeded`、`retry`、`dead` 五种状态过滤和按任务标识降序的游标分页。
3. Pydantic 公开模型、OpenAPI 和共享 Vue 管理页都不包含 `payload_json`、`scope_key` 或 `dedupe_key`。`last_error` 只来自 Worker 已净化的异常类型信息。
4. `POST /api/v1/jobs/{job_id}/retry` 只允许重试当前组织范围内的 `dead` 任务。仓储在同一事务中锁定任务行，把状态改回 `queued`，清零尝试次数并清除租约、错误和完成时间，同时写入 `jobs:retry` 审计事件。
5. `jobs:read` 和 `jobs:manage` 权限只授予内置 `admin` 角色。租户项目要求经过成员关系重新验证的组织标识；跨租户任务统一返回不存在。非租户项目固定限制在 `global` 范围。
6. 管理端可以筛选和分页，只在任务状态为 `dead` 时启用重试按钮。项目不生成取消、载荷查看或编辑、幂等键查看、运行中任务接管等功能。
7. SQLite 契约测试验证服务和迁移；CI 在 PostgreSQL 与 MySQL 真库验证列表范围、死信重试、权限、审计和公开字段边界。

## 结果

- Go、Java、Python 使用相同能力名、HTTP 契约、安全边界和共享管理页面，AI 无需为每个项目重复编写任务后台。
- 管理能力故意保持窄小；任务载荷排障仍应通过受控业务日志或专门的数据治理流程完成。
- 任务取消、批量重试、保留策略和人工改写载荷不属于 `0.1.0`。
