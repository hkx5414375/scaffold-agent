# ADR 0047：Python 原子 CSV 导入与审计导出

- 状态：已接受
- 日期：2026-09-01

## 背景

Python 生成项目已经具备 Blueprint CRUD、组织隔离和共享管理端，但仍缺少与 Go、Java 一致的小批量 CSV 交换能力。若让不同 AI 在 FastAPI 项目中临时拼装解析器、事务和下载接口，会重复消耗 Token，并容易出现部分提交、跨组织导出、公式注入或权限过宽。

## 决策

1. Python 适配器支持 `csv-import-export` `0.1.0`，要求 Blueprint 恰好包含一个可生成的业务实体，并同时支持 PostgreSQL 与 MySQL。
2. CSV 使用 Python 标准库按 Blueprint 可变字段顺序读写严格 UTF-8。布尔值只接受小写 `true`/`false`，整数限制为十进制 int64，时间要求 RFC3339，空白可选单元格转换为 null。
3. 请求和响应均限制为 5 MiB、1000 条数据。导入在调用仓储前完成整份文档解析与类型校验，只生成新 ID，不执行匹配、更新、删除或 Upsert。
4. 所有导入行与一条审计事件在同一个 SQLAlchemy 事务中提交；唯一约束冲突或审计失败会回滚整批数据。导出在同一事务中执行按 ID 排序、组织范围内的 1001 行有界查询，先按实际编码字节确认完整结果，再提交审计事件。
5. 文本导出采用与 Go、Java 相同的可逆单引号转义，防止电子表格把内容作为公式执行。导入模板可无损恢复以单引号或公式标记开头的原值。
6. `:import` 和 `:export` 是两项独立且仅授予管理员的权限。FastAPI、稳定 OpenAPI 和共享 Vue 管理端使用相同接口与限制；CSV 静态路由必须先于 CRUD 动态 ID 路由注册。
7. 仓储映射在数据库驱动返回无时区时间时显式恢复 UTC，避免驱动差异破坏 RFC3339 导出。

## 结果

- Go、Java、Python 现在使用同一个能力名、字段顺序、事务、租户、审计和电子表格安全契约，AI 无需按语言重新设计 CSV 底层。
- 同步能力继续拒绝大型迁移；更大的导入导出必须使用后台任务与对象存储，不得通过提高固定上限绕过。
- 生成项目运行时不依赖 Scaffold Agent，也不引入额外 CSV 包。
