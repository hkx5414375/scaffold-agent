# ADR 0053：ERP 库存与采购核心契约

- 状态：Proposed
- 日期：2026-09-02

## 背景

库存和采购是 ERP、商城履约、门店和内部物资系统都会重复实现的底层能力。不同 AI 临时生成这些能力时，最容易在数量精度、并发扣减、库存预留、重复请求、采购收货和历史可追溯性上产生不兼容实现。`0.1.0` 需要提供可独立组合的最小库存与采购核心，不依赖商品商城、订单、支付、CRM 或特定 AI。

## 决策

1. 新增 `erp-inventory` `0.1.0`。它生成独立的库存物料、仓库、余额、不可变库存流水、库存预留、采购单和采购单行。库存物料的 SKU 是库存范围内的稳定标识，不直接外键依赖 `commerce-catalog`；上层项目可以自行保存两者的映射。
2. 物料包含规范化为大写的 SKU、名称、计量单位以及 `active`、`archived` 状态；仓库包含规范化为大写的代码、名称以及相同状态。归档不删除历史，归档的物料或仓库不能继续接收新调整、预留或采购收货。
3. 数量一律使用有符号 64 位整数，HTTP JSON 中使用十进制字符串，禁止浮点数。一个物料和仓库只有一条余额；必须始终满足 `on_hand >= 0`、`reserved >= 0`、`reserved <= on_hand`，`available` 固定等于 `on_hand - reserved`。
4. 手工调整使用非零 `quantity_delta`，调整后不能让现有预留失去覆盖。每个实际库存变化都在同一事务里更新余额、追加不可修改的库存流水并写安全审计。客户端提供的幂等键在当前组织范围内唯一；相同键和相同命令重放返回第一次结果，不同命令复用同一键返回冲突。
5. 预留必须使用正数量和外部引用，且不能超过可用量。`active` 预留只能一次性转为 `released` 或 `consumed`：释放只减少预留量，消耗同时减少在手量和预留量。终态预留不可再次修改；创建、释放和消耗均追加库存流水并接受幂等键。
6. 采购单包含稳定单号、供应商名称、`draft`、`submitted`、`partially_received`、`received`、`cancelled` 状态和至少一条物料行。草稿只能提交；未收货的草稿或已提交采购单可以取消；收货只能发生在已提交或部分收货状态，单行累计收货不得超过订购量，全部收完后进入 `received`。每次收货增加在手量，并在同一事务写流水、审计和采购单版本。
7. 所有列表采用最多 100 条的标识 Keyset 分页；所有可变主数据、预留和采购单使用乐观版本。跨租户和不存在标识统一返回未找到，数据库错误不暴露驱动细节。
8. 权限固定为 `inventory:read`、`inventory:catalog:write`、`inventory:stock:manage` 和 `inventory:procurement:manage`。读取库存不代表可以调整库存，采购权限也不能绕过库存不变量。
9. 与 `organization-tenancy` 组合时必须使用 `0.3.0`。所有 ERP 表保存当前权限组织标识，事务开始时重复锁定并检查组织仍为 `active`；停用组织不能读写库存与采购数据。非租户项目使用单一空范围，但复用同一领域接口。
10. Vue 管理端只调用稳定库存 HTTP 契约。`0.1.0` 不实现销售订单、购物车、支付、自动补货、批次、序列号、保质期、成本核算、多单位换算、调拨或退货；这些能力通过稳定物料、仓库、预留、采购单和流水标识继续组合。

## 影响

- AI 可以选择一个能力包获得经过约束的库存并发与采购收货主干，不再重复设计余额、流水和幂等规则。
- 商城、订单、门店和 CRM 可以在不修改 ERP 表的前提下引用稳定标识，能力包之间保持可替换和可单独升级。
- ADR 在 Go、Java、Python 均完成 PostgreSQL/MySQL、共享 Vue 管理端和跨语言契约门禁前保持 `Proposed`；达到全部门禁后再改为 `Accepted`。
