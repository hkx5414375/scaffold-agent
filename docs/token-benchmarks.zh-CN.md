# Token 基准

## 结论

2026-09-02 的完整能力套件基准如下：

| 后端 | 生成文件 | 全量源码上下文估算 | Engine 工作流估算 | 节省估算 | 降幅 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Go | 185 | 380,954 | 1,913 | 379,041 | 99.50% |
| Java | 251 | 436,270 | 2,104 | 434,166 | 99.52% |
| Python | 234 | 483,496 | 1,982 | 481,514 | 99.59% |

这表示 AI 使用 Blueprint、Plan、分页预览、应用回执和校验结果时，不需要为了
创建同一项目而先把全部生成文件读取进上下文。它不表示模型生成源码本身一定
减少相同比例的厂商账单，也不比较不同模型的隐藏推理 token。

## 固定场景

三个场景都使用 PostgreSQL、Vue/Element Plus 管理端、Nuxt 商城、一个五字段业务
实体，以及组织租户、任务、通知、文件、缓存、任务管理、可观测性、CSV、审批、
商品、顾客、CRM 和 ERP 库存全部能力。只替换 `backend` 为 Go、Java 或 Python。

“全量源码上下文”是 Blueprint 和所有生成文件的 UTF-8 字节总数；“Engine 工作流”
是 Blueprint 加 `query`、`plan`、首个 20 项 `preview`、`apply` 和 `verify` JSON
结果。两者都用 `ceil(UTF-8 bytes / 4)` 计算，目的是提供稳定、跨模型、可在 CI
重算的相对指标，而不是模拟某一家 tokenizer。

## 回归门禁

- 每个后端降幅不得低于 90%。
- 单次完整 Engine 工作流不得超过 8,000 个估算 token。
- `conformance` 中更小的标准 Agent 工作流不得超过 4,096 个估算 token。
- 基准禁止访问网络、模型、数据库、编译器或包管理器。

本地重算：

```bash
go run ./cmd/scaffold-agent benchmark --json
```

任何增加输出字段、放宽分页或扩大工具说明的变更，都必须先通过上述预算门禁。
